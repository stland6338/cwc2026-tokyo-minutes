01

基調講演 — Claude Fable 5 / Mythos 5 発表

登壇: Caitlin / Diane Penn / Angela Jen / Cat Wu（Anthropic）VOD 0:00:54〜

開催数時間前にリリースされた第5世代モデルが主役。Fable 5 はほぼ全ベンチマークで SOTA。シングルショット正確性と数日規模の自律性が強みで、サイバー・生物・化学領域のリクエストは Opus 4.8 へ自動ルーティングする新しいセーフガードを採用。Mythos 5 は同基盤でセーフガードを解除した研究者向け（Project Glasswing）。

プラットフォームでは Managed Agents に Scheduled Deployments / Vaults が追加。Claude Code は平均開発者が週20時間利用、Dynamic Workflows・Claude Security 等を紹介。事例は楽天（リリース 13週→2週）、Spotify（移行期間 −90%）、メルカリ（出力 +90%）。

02

What's New in Claude Code

登壇: Charmaine（Anthropic Applied AI）VOD 1:16:52〜

新機能を「開発者体験」と「自律性」の2軸で総覧。DX側は Remote Control（スマホ/Webから継続）、チラつきを解消するフルスクリーンTUI、Voiceモード、刷新された Desktop GUI（Effortダイヤル付き）。

自律性側は「小さなことで止まる」問題への各個撃破: 分類器が権限判断する Auto Mode、ブランチ競合を防ぐ Worktrees、セッション横断の Auto-memory、エージェントチーム＋検証パスの Code Review、cron/Webhook/API で起動する Routines、フリート全体を操縦する Agent View、そして今週 GA の Dynamic Workflows（トリガーは「ultra code」へ変更）。

03

Canva AI 2.0 構築の教訓

登壇: Danny Wu（Canva Head of AI Products）VOD 1:56:30〜

数千万ユーザー（大半が無料）に AI を提供する4つの教訓。①成功指標: デザインは主観的（平均110回編集される）。レイテンシは品質指標以上に満足度と相関。②「今日の巧妙なハーネスは明日のデッドコード」— 3年で3回全面書き直し。資産は E2E evals。

③コスト: タスクバジェットで予算管理をモデルに委譲（advisory なので厳格な上限はシステム側で）。モデルルーティングはキャッシュ破壊で失敗し、Sonnet メイン＋Opus/Haiku サブエージェント方式へ — ヒット率80〜90%台を維持しコスト半減。④声の大きい少数の不満を evals に変換（画像アップスケーラー事例）。

04

Claude Managed Agents 詳説 ＋ 楽天対談

登壇: Jess Yen / Michael Cohen（Anthropic）＋ 梶氏（楽天）VOD 2:44:02〜

「ボトルネックは知能からインフラへ」。開発者の半数がインフラを本番化の最大障壁と回答する中、Managed Agents はインフラ＋プリミティブ＋可観測性をパッケージ提供する。構成は Agent（アイデンティティ）× Environment（世界）→ Session（サンドボックス自動供給）→ Events（永続トランスクリプト）。

新発表は Scheduled Deployments と Vaults。Vaults はコンテナに不透明トークンだけを置き、通信時に実シークレットを注入 — Claude は秘密値を見ない。楽天の梶氏は Memory + Dreaming による自己改善で「初期問題の90%を解消」、Vaults により監視エージェントの本番化が実現したと語った。

05

楽天における AI ナイゼーション

登壇: 梶氏（楽天グループ GM, AI for Business）VOD 4:31:30〜（日本語）

核心は「知能だけでは仕事は解決できない」。価値は「自律性 × 業務範囲」の2軸でスケールし、限界を決めるのはモデルではなくワークフローと組織デザイン。解けない2割の原因はほぼ組織側の制約 — IaC化・社内ポリシーのAI前提化・コンテキストの所在設計で解消する。

評価は自社本番PRを使う「楽天SWEベンチ」とタスク完了単価。Opus 4.7 が 4.6 比で本番PR解決3倍と出て即移行。Memory/Dreaming パイロットでクリティカルエラー97%削減。Fable 5 早期テストでは自己検証行動によるトークン効率の大幅改善を確認。

みずほ: AI前提の組織と内製開発の変革

登壇: 藤井氏（CAIO）/ 染谷健太郎氏（みずほFG）VOD 5:16:30〜（日本語）

07

The Capability Curve — 未来のモデルに向けて作る

登壇: Theo Chu（Anthropic Research PM）VOD 6:01:30〜

知能向上は3領域に現れる: ①計画してから行動（実行前に自己検出）②エラー回復（doom looping の終焉）③長いホライズン（100万トークン超の一貫性）。これらが「計画→実行→検証→修正」の自律ループを成立させる。

開発者への戦術: 今日のモデルが飽和しない evals を作り続ける／過去の失敗対策が堆積したスキャフォールディングを縮める（古い引用形式の指示を新モデルが忠実に守ってしまった実話）／adaptive thinking と effort ダイヤル／Auto Mode 的な統制付きアクセス／computer use 等の検証手段でループを閉じる。

失敗率は1/3に — そして検証がループを閉じる

08

NRI: エンタープライズはどうモデルを選んでいるのか

登壇: 北村雄貴氏（NRI AIソリューション推進部長）VOD 6:46:30〜（日本語）

SIer の視点で「モデルの優劣」ではなく「業務へのフィット」を評価する枠組みを解説。約款・規定など日本語業務文書の解釈、帳票の読解、「わからない」と言える能力を、新モデルが出るたび即日で社内ベンチマーク（Fable 5 も当日評価。ZDR 周りの注意点にも言及）。

Claude 選定の最大理由は複雑な指示への追従性 — human-in-the-loop の人間介在を最小化できるから。評価設計の原則は「業務単位の塊＋ベースライン＋ルーブリック（Define Outcomes）」をパイプライン化し、新モデル到来時に業務側が自動で恩恵を得る再評価ループを作ること。ダブルチェック業務の AI 置換で効率50%向上の実績（公式ケーススタディ掲載）。

09

エージェントを大規模・低コストにデプロイする

登壇: Brad Abrams / Rod Howorth（Anthropic）VOD 7:31:30〜

最重要はプロンプトキャッシング: 90%割引・高速化・レート制限非カウント。Console の新ダッシュボードでヒット率を確認し80%台を目指す（Claude API スキルに「improve my cache hit rate」と頼むだけでも改善可能）。

コンテキストエンジニアリング3技法 — Tool Search Tool（ツール定義を外す。Lovable はトークン−10%＋判断品質向上）、Programmatic Tool Calling（結果から必要な数%だけコードで抽出）、Compaction（閾値で要約リセット。Hex は自前実装300行を削除）。さらに Advisor 戦略: Sonnet メインに Opus/Fable を相談役として持たせ、デモでは Sonnet の見落としを Opus が訂正。WIF（APIキー不要化）とモデルフォールバックも紹介。

1Mトークンを「思考」のために空ける（議事録より作図）

10

ソフトウェア開発の民主化とコミュニティ（最終セッション）

登壇: 辻 純一郎氏（Anthropic Japan Developer Community Lead）VOD 8:16:30〜（日本語）

「昨年秋ごろからソフトウェアを作る障壁はほぼ消えた。制約は『コードを書けるか』から『課題を言語化できるか』へ移り、最も価値を持つのはドメインの深い知識」。Build with Opus ハッカソン（応募1.3万人）では上位5組中4組が非エンジニア — 1位の弁護士は「コードを1行も書いていない」。

企業導入はボトムアップが鍵: Zapier は全社ハッカソン後に社員数を超える800以上のエージェントが誕生し97%が毎日利用。そして日本での Claude Community Ambassador 募集開始を発表（グローバルは37カ国・107都市・約300イベント）。

「優勝したなんて信じられない。コードを1行も読んでいない」
